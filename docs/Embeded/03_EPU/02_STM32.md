## 手册

1. 数据手册（Datasheet）：描述芯片的外部特性和硬件指标，包括核心参数、引脚定义、电气特性及封装信息，是硬件选型和电路设计的依据。
2. 参考手册（Reference Manual, RM）：详解芯片内部所有外设单元的工作原理、存储器结构和寄存器配置，是嵌入式软件工程师进行底层驱动开发的核心指导文档。
3. 编程手册（Programming Manual, PM）：阐述ARM Cortex-M系列内核的架构、指令集、异常和中断处理机制，适用于需要深度内核优化或系统级编程的开发者。
4. 勘误手册（Errata Sheet）：列出特定芯片版本中经确认的硬件设计缺陷与操作限制，并提供相应的软件规避措施或注意事项，是解决疑难杂症的关键文档。

## STM32Cube

### 介绍

[STM32Cube生态系统](https://www.st.com.cn/content/st_com/zh/ecosystems/stm32cube-ecosystem.html)是面向STM32微控制器和微处理器的完整软件解决方案。它既适用于为STM32寻找完整、免费开发环境的用户，也适用于已经拥有集成开发环境（包括Keil或iAR）的用户，他们可以在其中轻松集成STM32CubeMX、STM32CubeProgrammer或STM32CubeMonitor等各种组件。

STM32Cube 生态系统包括嵌入式软件和软件工具两大部分。

### MCU和MPU包

[STM32Cube MCU和MPU包](https://www.st.com.cn/zh/embedded-software/stm32cube-mcu-mpu-packages.html)包括各个 STM32 系列 MCU 的固件库和一些扩展库，固件库包含 STM32 MCU 的 HAL 驱动库和移植好的各种中间件，例如嵌入式操作系统 FreeRTOS、文件系统FatFS等。提供基于HAL/LL等高级抽象层的固件函数库、驱动源码和丰富例程，旨在简化开发流程，提升代码可移植性和开发效率。

#### HAL库

HAL库（Hardware Abstraction Layer）提供了硬件抽象和跨系列兼容性。HAL库的目标是提供一套统一的、高级的API，让同样的代码在不同的STM32系列芯片（如F1, F4, L4）上都能编译运行，至少是减少移植工作量。它封装了底层的硬件差异，提供了更“傻瓜化”的操作方式。

HAL库名称是 "STM32F1xx_HAL_Driver"，文件命名方式是"stm32f1xx_hal_xxx.c/h"。

#### LL库

LL库（Low-Layer）提供了轻量级、高效率与性能。LL库可以看作是HAL库的“底层伴侣”或“轻量级标准库”。它同样提供了一系列函数来操作寄存器，但比标准库更轻量、更直接，几乎是一一对应寄存器的位操作，效率极高。它没有HAL库复杂的状态机和检查机制。

库名称是 "STM32F1xx_HAL_Driver"，文件命名方式是"stm32f1xx_ll_xxx.c/h"。ST当前主推的库之一，**与HAL库互补，通常与HAL库共存于同一个工程中，可以混合使用**。

#### 标准库

[标准外设库（Standard Peripheral Library）](https://www.st.com.cn/zh/embedded-software/stm32-standard-peripheral-libraries.html)不是STM32Cube生态的内容，它是对直接寄存器操作进行的封装。它提供了一系列函数和结构体，让你可以用C语言去配置芯片的各个外设寄存器，而不用直接去写晦涩的十六进制数。它是对底层寄存器的一个“薄封装”。

库名称是 "STM32F10x_FWLib"，文件命名方式是"stm32f10x_xxx.c/h"。标准库**已停止更新和维护**。ST官方从2014年左右开始，对新出的芯片（如F7, H7, L4, L5等）不再提供标准库，全面转向HAL/LL库。目前仅在一些经典系列（如F1, F4）上使用广泛。

#### 中间件

### 扩展包

[STM32Cube扩展包](https://www.st.com.cn/zh/embedded-software/stm32cube-expansion-packages.html)通过附加的软件模块来补充STM32Cube MCU软件包，这些模块不仅包括面向外部配套芯片的特定驱动程序，还涵盖了特定应用的中间件。这些扩展包为开发人员提供了许多应用领域中真实用例的简化实现，如传感、电源管理、连接和音频，同时还包含针对意法半导体开发板和支持的IDE的预配置项目示例，便于轻松入门。

#### CMSIS Packs

Pack文件（也叫设备家族包、软件包）是Keil MDK为了支持特定芯片厂商（如ST、NXP、TI等）的微控制器而提供的“资源库”和“支持文件集”。没有安装对应的Pack，Keil就无法识别你的STM32芯片，也无法进行编译和调试。

- 设备描述文件
- 启动文件
- CMSIS设备驱动
- 标准库STM32Cube HAL/LL库 / 标准库
- 系统文件
- Flash编程算法
- 调试系统视图文件
- 软件组件和例程

安装方式：

1. 手动通过Pack Installer安装，点击 Project -> Manage -> Pack Installer。（需梯子）
2. 在 [Keil官网Pack页](https://www.keil.arm.com/packs/) 找到对应的.pack文件下载安装。

安装路径：

C:\Users\<你的用户名>\AppData\Local\Arm\Packs\Keil\STM32F1xx_DFP\<版本号>

### keil编译信息分析

Program size: Code, RO-data , RW-data, ZI-data具体代表什么？

1. Code 是代码占用的空间。
2. RO-data是 Read Only 只读常量的大小，如const型。
3. RW-data是（Read Write） RW是可读可写变量，就是初始化时候就已经赋值了的，RW + ZI就是你的程序总共使用的RAM字节数。
4. ZI-data是（Zero Initialize） 没有初始化的可读写变量的大小，就是程序中用到的变量并且被系统初始化为0的变量的字节数，keil编译器默认是把你没有初始化的变量都赋值一个0，这些变量在程序运行时是保存在RAM中的。

Total ROM Size (Code + RO Data + RW Data)这样所写的程序占用的ROM的字节总数，也就是说程序所下载到ROM flash 中的大小。为什么Rom中还要存RW，因为掉电后RAM中所有数据都丢失了，每次上电RAM中的数据是被重新赋值的，每次这些固定的值就是存储在Rom中的，为什么不包含ZI段呢，是因为ZI数据都是0，没必要包含，只要程序运行之前将ZI数据所在的区域一律清零即可。包含进去反而浪费存储空间。

MCU执行过程是先将RW从ROM中搬到RAM中，因为RW是变量，变量不能存在ROM中。然后将ZI所在的RAM区域全部清零，因为ZI区域并不在Image中，所以需要程序根据编译器给出的ZI地址及大小来将相应得RAM区域清零。ZI中也是变量，同理：变量不能存在ROM中。ROM中的指令完成了这两项工作后C程序才能正常访问变量。否则只能运行不含变量的代码。
